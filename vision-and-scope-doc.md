# Документ о концепции и границах
## Проект: Личный кабинет сотрудника (внутренний портал)

**Версия:** 1.0 (первый релиз — только для внутренних пользователей)  
**Дата:** 2026-04-08  
**Статус:** Согласовано с заказчиком

---

## 1. Бизнес требования

### 1.1 Исходные данные

В настоящий момент сотрудники (менеджеры) выставляют счета в Excel. Это приводит к следующим проблемам:

- Сотрудники **забывают выставлять счета вовремя**
- Возникают **ошибки в ценообразовании**
- Руководитель тратит много времени на **ручной контроль**

Руководство приняло решение автоматизировать процесс и заказать личный кабинет для сотрудников, чтобы работать не в Excel, а во внутренней системе.

### 1.2 Возможности бизнеса

**Бизнес-задача:**  
Автоматизировать выставление счетов и контроль за ними, чтобы снизить ручной труд и количество ошибок.

**Среда использования:**  
Корпоративная информационная система. Пользователи — сотрудники компании (менеджеры, руководители, стажёры, администратор).  
Доступ через браузер с компьютера в офисе. В дальнейшем — мобильная версия для работы в командировках.

**Потребности пользователей:**

- Менеджер хочет быстро выставить счёт, применить скидку (в рамках своего лимита), не забывать про клиентов, которые давно не покупали
- Руководитель хочет видеть счета всех подчинённых, утверждать скидки выше лимита, тратить меньше времени на контроль
- Администратор хочет заводить пользователей и смотреть логи (но не работать со счетами)
- Интегратор хочет загружать прайсы (Excel)

**Критичные требования к качеству (из интервью):**

- Максимальное время отклика на любое действие пользователя — 3 секунды.
- Система не должна запрашивать подтверждения для стандартных операций.
- Пользователь не должен видеть данные других сотрудников (кроме руководителя, который видит свой отдел).

### 1.3 Бизнес-цели

| № | Цель | Измерение (KPI) | Способ проверки |
|---|------|------------------|------------------|
| 1 | Ускорить выставление счетов | Сокращение среднего времени от начала создания до отправки счёта в 2 раза | Замер в системе (логи времени между действиями «создан» и «отправлен») до и после внедрения |
| 2 | Снизить количество ошибок в ценообразовании | Снижение количества ошибок: применение неактуального прайс-листа и пропуск согласованных скидок | Сравнение жалоб клиентов и количества перевыставленных счетов за месяц до и после внедрения |
| 3 | Уменьшить время контроля для руководителя | Снижение времени руководителя на операционный контроль выставления счетов | Опрос руководителя через 1 месяц после запуска |
| 4 | Перейти с Excel на ЛК | Доля счетов, созданных в ЛК, ≥95% через 1 месяц после запуска | Логи системы + данные 1С |

### 1.4 Критерии успеха

Проект считается успешным, если:

1. Снижение числа жалоб менеджеров на процесс выставления счетов до минимального уровня.
2. Исключение практики личных обходов руководителем для проверки факта выставления счетов.
3. Снижение количества жалоб клиентов на задержки и ошибки в выставленных счетах.
4. Увеличение скорости выставления счёта в 2 раза по сравнению с текущим процессом (замер по логам).
5. Обеспечение отклика системы не более 3 секунд на любое действие пользователя.

**Факторы успеха, которые организация может контролировать:** обучение менеджеров, качество интеграции с 1С, скорость реакции на баги.  
**Факторы вне контроля:** качество интернета в офисе, состояние старого сервера.

### 1.5 Положение о концепции

Для менеджеров по продажам и их руководителей, которые сейчас тратят время на ручное выставление счетов в Excel, допускают ошибки в прайсах и скидках, а руководитель вынужден лично контролировать каждый счёт. Личный кабинет сотрудника — это веб-портал, который позволяет выставлять счета с автоматическим применением скидок (в пределах лимита сотрудника), выбирать клиента из списка (с подсветкой «давно не покупал») и получать историю действий. В отличие от текущего процесса в Excel, наш продукт снижает количество ошибок, ускоряет выставление счетов в 2 раза и даёт руководителю прозрачный контроль без лишних вопросов.

### 1.6 Бизнес-риски

| Риск | Вероятность | Влияние | Меры снижения |
|------|-------------|---------|----------------|
| Менеджеры продолжат работать в Excel | Средняя | Высокое | Обучение, контроль руководителя, удобство ЛК. KPI по доле счетов из ЛК |
| Старый сервер + плохой интернет → тормоза >3 сек | Высокая | Критическое | Очередь запросов, кэш, компромисс по времени (но 3 сек — жёсткое требование) |
| Данных для расчёта лимита скидок нет в системе (стаж, план) | Высокая | Среднее | **Стаж**: пока нет данных из отдела кадров — использовать константу 1 год. **План**: если не введён на месяц — использовать константу 10% для бонуса |
| Бухгалтер не захочет заходить в ЛК | Высокая | Низкое | Уже учтено: ЛК для бухгалтера не делаем. Он работает с PDF и распечатками |
| Интеграция со старой 1С не сработает как надо | Средняя | Высокое | Очередь на отправку, повтор каждые 15 мин, уведомление админу после 3 неудач. Резервный план — ручной экспорт |

### 1.7 Предположения и зависимости

**Предположения :**

1. **Данные о стаже** отсутствуют в системе. В первом релизе стаж всех менеджеров = 1 год. Позже админ вручную внесёт данные из бумажных карточек (шкаф №3, комната 405, доступ через Светлану Ивановну).
2. **Логин для менеджеров без почты** создаётся админом вручную по правилу `фамилия.manager`. Если занято — добавить число (`ivanov.manager2`). Система не генерирует автоматически.
3. **Пароли** у пользователей отсутствуют. Временный пароль = 123, пользователь поменяет при первом входе.
4. **Почта** есть не у всех. Восстановление пароля пока через звонок админу.
5. **Бухгалтер** не заходит в ЛК. Ему менеджер носит распечатку или скидывает PDF по почте.
6. **Курьер** получает отдельный экран (не ЛК) с одной кнопкой «Заказы на сегодня». В первом релизе курьера нет. 
7. **Клиенты** — не в первом релизе, но данные для них готовятся.
8. **Стажёры** имеют одного наставника и видят только его счета. Статус меняет админ вручную по приказу.
9. **Планы продаж** вносит руководитель вручную в экран «Планы продаж». Если плана нет на месяц — используется константа 10% для бонуса. Скидки не блокируются.
10. **Приоритет типов скидок** (от высшего к низшему): Индивидуальная → Сезонная → Накопительная. Применяется только одна, не суммируются.
11. **Регион менеджера** — одно поле в карточке, заполняет админ. Если не указан — базовый федеральный прайс.

**Зависимости :**

1. **1С** — интеграция **только из ЛК в 1С**. Передаём счета с пометкой «Счёт из ЛК». Обратно ничего не синхронизируется (остатки, оплаты — смотрим отдельно или вручную). 
2. **Почтовый сервер** — для отправки PDF клиентам и ежедневной рассылки Excel в 09:00 (только две таблицы: остатки по частым товарам и выставленные счета за период). 
3. **Excel** — для загрузки прайсов (интегратор) и выгрузки отчётов.
4. **Кадровые данные** (дата приёма) — должны быть внесены в систему вручную админом после запуска, иначе лимиты скидок останутся некорректными.
5. **Руководитель / Админ** — выделение времени на заведение пользователей и ежемесячный ввод планов продаж.

**Последствия нарушения зависимостей:**  
Если 1С не будет интегрирована должным образом, счета не будут передаваться, и менеджеры вернутся к Excel. Если не внести реальные даты приёма — лимиты скидок будут несправедливыми. Если руководитель не введёт план — менеджеры не получат бонус +5% к лимиту (будет константа 10%).

## 2. Рамки и ограничения проекта

### 2.1 Основные функции (первый релиз)

| ID | Функция | Краткое описание |
|----|---------|------------------|
| F1 | **Вход и безопасность** | Вход по логину/паролю, запоминание сессии, блокировка при попытке взлома (без капчи), смена пароля |
| F2 | **Дашборд** | Виджеты: остатки по частым товарам, кол-во и сумма счетов (сегодня/неделя), просроченные счета, новые заявки, напоминания (дни рождения за 3 дня, просрочки), выполнение плана продаж (с цветным индикатором). У руководителя — сводка по всем менеджерам. |
| F3 | **Формирование счёта (PDF)** | Выбор клиента из списка (или добавление нового вручную), подсветка красным «давно не покупал», формирование PDF. Применение скидки по приоритету (индивид. → сезонная → накопительная) с проверкой лимита менеджера. |
| F4 | **Скидки** | **Накопительная** (за 12 мес из 1С), **Сезонная** (загружается Excel, действует авто), **Индивидуальная** (назначает руководитель). **Лимит менеджера:** стаж <6 мес → 5%; 6–24 мес → 10%; >24 мес → 15% +5% если план выполнен ≥100%. **Порог согласования:** скидка требует одобрения руководителя, если превышает лимит ИЛИ >15% ИЛИ в рублях >50 000 ₽. Если руководитель не ответил 2 часа → автоотказ, счёт без скидки. |
| F5 | **Просмотр документов** | Свои счета и акты |
| F6 | **История действий** | Менеджер видит историю за 3 дня, руководитель — за месяц. Удаляется автоматически ежедневно в 02:00. Безвозвратно, без архива. |
| F7 | **Экспорт в Excel на почту** | **Только две таблицы:** 1) Остатки по частым товарам, 2) Выставленные счета за период (месяц/неделя на выбор при настройке). Рассылка раз в день в 09:00. Настраивает руководитель. |
| F8 | **Сохранение настроек** | Кнопка «сохранить настройки» (что показывать на главной) |
| F9 | **Мобильная версия** | Только чтение (остатки, счета, план, напоминания). Нельзя выставить счёт, применить/согласовать скидку. Отдельная задача, не в первом релизе. |
| F10 | **Управление пользователями** | Только админ заводит учётные записи. Админ **не** создаёт, не редактирует и не удаляет счета. Только пользователи и логи. |
| F11 | **Интеграция с 1С** | Только из ЛК в 1С: счёт (номер, дата, клиент, сумма, товары, скидка) + пометка «Счёт из ЛК». Если 1С недоступна — очередь, повтор каждые 15 мин, после 3 неудач — уведомление админу. |
| F12 | **Уведомления (по умолчанию)** | Все напоминания включены (просроченные счета, низкие остатки, день рождения клиента) — настройка позже |

### 2.2 Объем первоначально запланированной версии (Выпуск 1)

- **Только внутренние пользователи** (менеджер, стажёр, руководитель, директор (только просмотр), администратор). Бухгалтера нет. Курьера нет в первом релизе.
- **Роли:**
  - *Менеджер*: создаёт счета, применяет скидки в пределах лимита.
  - *Стажёр*: видит счета только своего наставника (один наставник).
  - *Помощник менеджера*: флаг в карточке, создаёт счета от имени менеджера, просматривает его счета, не меняет скидки выше лимита, не удаляет счета.
  - *Руководитель*: видит счета только своего отдела. Утверждает скидки по порогу.
  - *Директор*: только просмотр всех счетов, не утверждает.
  - *Администратор*: управление пользователями, просмотр логов, ручное заведение логинов, смена статуса стажёра, блокировка ЛК при увольнении. Не работает со счетами.
- **Функции из п. 2.1** — все перечисленные, кроме мобильной версии и курьера (они отложены).
- **Интеграция:** только ЛК → 1С (счета). Остатки, оплаты, прайсы — не синхронизируются.
- **Производительность:** максимум 3 секунды на любое действие.

### 2.4 Ограничения и исключения. Out of Scope для первого релиза

- Клиенты не имеют доступа. Функциональность для клиентов перенесена на следующий релиз.
- Бухгалтер **не получает ЛК**. Работает с бумагой или PDF.
- Курьер **не получает ЛК**. Будет отдельный экран в Выпуске 2.
- Администратор **не создаёт и не редактирует счета**.
- Нет авторизации через соцсети / Госуслуги.
- Нет отдельной регистрации. Учётные записи создаёт только администратор.
- Нет восстановления пароля через SMS. Только звонок админу.
- Нет капчи при входе.
- Нет лишних подтверждений операций.
- Нет показа чужих данных менеджерам (кроме руководителя в своём отделе и стажёра — счета наставника).
- **История действий не архивируется**, удаляется безвозвратно.
- **Экспорт в Excel на почту** — только две таблицы, не все.
- **Интеграция с 1С** — только в одну сторону (ЛК → 1С).

### 3.3 Особенности развертывания

**Доступ к системе:**
- Пользователи в одном офисе, но интернет нестабильный.
- Доступ через браузер с рабочего компьютера.
- Мобильная версия — только чтение, в Выпуске 2.

**Изменения инфраструктуры:**
- Интеграция с 1С только на отправку счетов (очередь, повтор 15 мин, 3 попытки).
- Нужна очередь запросов, чтобы тяжёлые отчёты не тормозили работу.
- Интеграция с почтовым сервером для отправки PDF и ежедневной рассылки Excel в 09:00.

**Обучение и модификация процессов:**
- Менеджеры обучаются работе в ЛК.
- Руководитель учится утверждать скидки (2 часа ожидания, иначе автоотказ).
- Админ заводит всех пользователей вручную (логин по правилу `фамилия.manager`).
- Руководитель ежемесячно вручную вводит планы продаж в экран «Планы продаж».
- Админ вручную меняет статус стажёра по приказу и блокирует ЛК при увольнении.
- Админ вручную вносит регион менеджера и стаж (из бумажных карточек отдела кадров).

**Миграция данных:**
- Логин: если есть почта — email, иначе `фамилия.manager` (админ вручную).
- Стаж: пока нет данных → константа 1 год.
- План: пока не введён → константа 10% для бонуса.
- Пароли: временный 123, меняется при первом входе.
- Регион: не указан → базовый федеральный прайс.

**Дополнительно:**
Учётные записи создаются только для тех, кому они действительно нужны по ролям. Бухгалтер ЛК не получает. Курьер получит отдельный экран в Выпуске 2. Администратор не работает со счетами — это строгое ограничение.
