# Документ о концепции и границах
## Проект: Личный кабинет сотрудника (внутренний портал)

**Версия:** 1.0 (первый релиз — только для внутренних пользовающих)  
**Дата:** 2026-04-07  
---

## 1. Бизнес требования

### 1.1 Исходные данные

В настоящий момент сотрудники (менеджеры) выставляют счета в Excel. Это приводит к следующим проблемам:

- Сотрудники **забывают выставлять счета вовремя** (клиент звонит, менеджер говорит «завтра отправлю»)
- Возникают **ошибки в ценообразовании** (берут не тот прайс, забывают применить скидку)
- Руководитель тратит много времени на **ручной контроль** (обходит сотрудников с вопросом «Ты выставил?»)

Руководство приняло решение автоматизировать процесс и заказать личный кабинет для сотрудников, чтобы работать «не в Excel, а в нормальной системе».

### 1.2 Возможности бизнеса

**Бизнес-задача:**  
Автоматизировать выставление счетов и контроль за ними, чтобы снизить ручной труд и количество ошибок.

**Среда использования:**  
Корпоративная информационная система. Пользователи — сотрудники компании (менеджеры, руководители, стажёры, администратор).  
Доступ через браузер с компьютера в офисе (интернет «не очень», сервер «старый»). В дальнейшем — мобильная версия для работы в командировках.

**Потребности пользователей:**

- Менеджер хочет быстро выставить счёт, применить скидку (в рамках своего лимита), не забывать про клиентов, которые давно не покупали
- Руководитель хочет видеть счета всех подчинённых, утверждать скидки выше лимита, тратить меньше времени на контроль
- Администратор хочет заводить пользователей и смотреть логи
- Интегратор хочет загружать прайсы (Excel)

**Критичные требования к качеству (из интервью):**

- «Нельзя долго грузиться — максимум три секунды на любую кнопку»
- «Нельзя, чтобы система просила лишние подтверждения»
- «Нельзя показывать чужую информацию»

### 1.3 Бизнес-цели

| № | Цель | Измерение (KPI) | Способ проверки |
|---|------|------------------|------------------|
| 1 | Ускорить выставление счетов | **В 2 раза быстрее** (среднее время от начала создания до отправки счёта) | Замер в системе / опрос менеджеров (до и после внедрения) |
| 2 | Снизить количество ошибок в ценообразовании | Меньше случаев, когда берут «не тот прайс» или «забывают скидку» (конкретное снижение — уточнить) | Сравнение жалоб клиентов и перевыставленных счетов |
| 3 | Уменьшить время контроля для руководителя | Руководитель перестаёт ходить и спрашивать «Ты выставил?» | Опрос руководителя через 1 месяц после запуска |
| 4 | Перейти с Excel на ЛК | **Доля счетов, созданных в ЛК, ≥95%** через 1 месяц после запуска | Логи системы + данные 1С |

### 1.4 Критерии успеха

Проект считается успешным, если:

1. **Менеджеры не ноют** (устные жалобы на процесс выставления счетов снизились до минимума)
2. **Руководитель не дёргает** (контроль перестал требовать ежедневных обходов)
3. **Клиенты не жалуются** (снизилось количество жалоб на задержки и ошибки в счетах)
4. **Скорость работы** — «чувствуется, что быстрее», а по замерам — в 2 раза
5. **ЛК работает без тормозов** (отклик ≤3 секунд)

**Факторы успеха, которые организация может контролировать:** обучение менеджеров, качество интеграции с 1С, скорость реакции на баги.  
**Факторы вне контроля:** качество интернета в офисе, состояние старого сервера.

### 1.5 Положение о концепции

**Для** менеджеров по продажам и их руководителей,  
**которые** сейчас тратят время на ручное выставление счетов в Excel, допускают ошибки в прайсах и скидках, а руководитель вынужден лично контролировать каждый счёт,  
**личный кабинет сотрудника** — это веб-портал,  
**который** позволяет выставлять счета с автоматическим применением скидок (в пределах лимита сотрудника), выбирать клиента из списка (с подсветкой «давно не покупал») и получать историю действий (3 дня для менеджера, месяц для руководителя),  
**в отличие от** текущего процесса в Excel,  
**наш продукт** снижает количество ошибок, ускоряет выставление счетов в 2 раза и даёт руководителю прозрачный контроль без лишних вопросов.

### 1.6 Бизнес-риски

| Риск | Вероятность | Влияние | Меры снижения |
|------|-------------|---------|----------------|
| Менеджеры продолжат работать в Excel | Средняя | Высокое | Обучение, контроль руководителя, удобство ЛК |
| Старый сервер + плохой интернет → тормоза >3 сек | Высокая | Критическое | Очередь запросов, кэш, компромисс по времени |
| Данных для расчёта лимита скидок нет в системе (дата приёма) | Высокая | Среднее | Временно — константа (1 год стажа) |
| Бухгалтер не захочет заходить в ЛК | Высокая | Низкое | Уже учтено: ЛК для бухгалтера не делаем, высылаем PDF |
| Интеграция со старой 1С не сработает как надо | Средняя | Высокое | Привлечение разработчиков 1С, резервный план (Excel-выгрузки) |

### 1.7 Предположения и зависимости

**Предположения (Assumptions):**

1. **Данные о стаже** отсутствуют в системе → в первом релизе стаж всех менеджеров = 1 год (потом поправим)
2. **Пароли** у пользователей отсутствуют → временный пароль = 123 (пользователь меняет при первом входе)
3. **Почта** есть не у всех → восстановление пароля пока через звонок админу
4. **Бухгалтер** не будет заходить в ЛК → ему менеджер носит распечатку или скидывает PDF по почте
5. **Курьер** получает отдельный экран (не полноценный ЛК)
6. **Клиенты** — не в первом релизе, но данные для них готовятся («заглушка»)
7. **Стажёры** — временные, им можно сделать упрощённую форму (без сохранения истории)
8. **Руководитель** = он же администратор (в первом релизе)
9. **Планы продаж** для расчёта лимита скидок будут предоставлены позже (в первом релизе могут отсутствовать)
10. **Приоритеты типов скидок** будут предоставлены позже

**Зависимости (Dependencies):**

1. **1С** (старая, возможно обновление) — интеграция обязательна для обмена данными о счетах, остатках, клиентах
2. **Почтовый сервер** — для отправки PDF клиентам
3. **Excel** — для загрузки прайсов (интегратор)
4. **Кадровые данные** (дата приёма) — должны быть внесены в систему после запуска (иначе лимиты скидок останутся некорректными)
5. **Руководитель / Админ** — выделение времени на заведение пользователей и настройку

**Последствия нарушения зависимостей:**  
Если 1С не будет интегрирована должным образом, счета не будут синхронизироваться, и менеджеры вернутся к Excel. Если не внести реальные даты приёма — лимиты скидок будут несправедливыми (новички получат слишком высокие скидки, опытные — слишком низкие).

## 2. Рамки и ограничения проекта

### 2.1 Основные функции (первый релиз)

| ID | Функция | Краткое описание |
|----|---------|------------------|
| F1 | **Вход и безопасность** | Вход по логину/паролю, запоминание сессии, блокировка при попытке взлома (без капчи), смена пароля |
| F2 | **Дашборд** | Остатки по часто продаваемым товарам (система сама определяет «частые», если не поймёт — показывает все) |
| F3 | **Формирование счёта (PDF)** | Выбор клиента из списка (или добавление нового вручную), подсветка красным «давно не покупал», формирование PDF |
| F4 | **Скидки** | 3 типа скидок (приоритеты уточняются), применение в пределах лимита менеджера (лимит = f(стаж, план) — пока стаж = 1 год константа) |
| F5 | **Просмотр документов** | Свои счета и акты |
| F6 | **История действий** | Менеджер — за 3 дня, руководитель — за месяц (что именно логировать — уточняется) |
| F7 | **Экспорт в Excel** | Автоматическая выгрузка всех таблиц, которые видит менеджер, раз в день на почту (время выбирает менеджер или руководитель) |
| F8 | **Сохранение настроек** | Кнопка «сохранить настройки» (что показывать на главной) |
| F9 | **Мобильная версия** | Через браузер на телефоне (без отдельного приложения) |
| F10 | **Управление пользователями** | Только админ заводит учётные записи (нет самостоятельной регистрации) |
| F11 | **Интеграция с 1С** | Обмен данными (направления уточняются) |
| F12 | **Уведомления (по умолчанию)** | Все напоминания включены (просроченные счета, низкие остатки, день рождения клиента) — настройка позже |

- **Роли:** как указано выше. Для супервайзера — права как у руководителя, но без утверждения скидок

- **Интеграция:** с 1С (старой, возможно обновление), с Excel (загрузка прайсов), с почтовым сервером
- **Производительность:** максимум 3 секунды на любое действие (компромисс из-за старого сервера и плохого интернета)

| **Стажёр** | Возможность выставлять счета (но с ограничением скидки ≤5%) | Временный пользователь, нужна упрощённая форма | Не превысить лимит скидки, не допустить ошибок | Временный статус, может не быть полноценного ЛК |
| **Руководитель отдела продаж** | Прозрачный контроль, меньше времени на «дёрганье», утверждение скидок выше порога | Сильная поддержка | Видеть счета всех менеджеров, утверждать скидки, не тратить лишнее время | Должен быть доступ ко всем ЛК менеджеров |

### 3.3 Особенности развертывания

**Доступ к системе:**
- Пользователи находятся в одном офисе, но интернет «не очень», сервер старый
- В командировках — мобильная версия через браузер (отдельное приложение позже)
- Доступ через интрасеть (внутренняя сеть компании)

**Изменения инфраструктуры:**
- Возможно обновление 1С (или не обновление — не определено)
- Нужна очередь запросов или кэш, чтобы тяжёлые отчёты руководителя не тормозили работу менеджеров
- Нужна интеграция с почтовым сервером для отправки PDF

**Обучение и модификация процессов:**
- Менеджеры должны быть обучены работе в ЛК (иначе останутся в Excel)
- Руководитель должен получить доступ к ЛК всех менеджеров и научиться утверждать скидки
- Админ должен завести всех пользователей (самостоятельной регистрации нет)
- Временный пароль = 123, пользователь меняет при первом входе (или сообщают устно)

**Миграция данных:**
- Данные о пользователях (логин, имя) — частично есть
- Дата приёма — отсутствует → константа 1 год (потом внесут)
- Пароли — отсутствуют → временный 123

**Дополнительно:**
- Сделать так, чтобы «не было видно, кому ЛК не нужен» (менеджеры обидятся). У бухгалтера и других «пустых» пользователей ЛК технически есть, но он пустой или заблокирован.
