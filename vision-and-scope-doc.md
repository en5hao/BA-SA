# Документ о концепции и границах
## Проект: Личный кабинет сотрудника (внутренний портал)

**Версия:** 1.0 (первый релиз — только для внутренних пользовающих)  
**Дата:** 2026-04-07  
---

## 1. Бизнес требования

### 1.1 Исходные данные

В настоящий момент сотрудники (менеджеры) выставляют счета в Excel. Это приводит к следующим проблемам:

- Сотрудники **забывают выставлять счета вовремя** 
- Возникают **ошибки в ценообразовании** 
- Руководитель тратит много времени на **ручной контроль** 

Руководство приняло решение автоматизировать процесс и заказать личный кабинет для сотрудников, чтобы работать не в Excel, а во внутренней системе.

### 1.2 Возможности бизнеса

**Бизнес-задача:**  
Автоматизировать выставление счетов и контроль за ними, чтобы снизить ручной труд и количество ошибок.

**Среда использования:**  
Корпоративная информационная система. Пользователи — сотрудники компании (менеджеры, руководители, стажёры, администратор).  
Доступ через браузер с компьютера в офисе. В дальнейшем — мобильная версия для работы в командировках.

**Потребности пользователей:**

- Менеджер хочет быстро выставить счёт, применить скидку (в рамках своего лимита), не забывать про клиентов, которые давно не покупали
- Руководитель хочет видеть счета всех подчинённых, утверждать скидки выше лимита, тратить меньше времени на контроль
- Администратор хочет заводить пользователей и смотреть логи
- Интегратор хочет загружать прайсы (Excel)

**Критичные требования к качеству (из интервь):**

- Максимальное время отклика на любое действие пользователя — 3 секунды.
- Система не должна запрашивать подтверждения для стандартных операций.
- Пользователь не должен видеть данные других сотрудников.

### 1.3 Бизнес-цели

| № | Цель | Измерение (KPI) | Способ проверки |
|---|------|------------------|------------------|
| 1 | Ускорить выставление счетов | **В 2 раза быстрее** (среднее время от начала создания до отправки счёта) | Замер в системе / опрос менеджеров (до и после внедрения) |
| 2 | Снизить количество ошибок в ценообразовании | Снижение количества ошибок в ценообразовании: применение неактуального прайс-листа и пропуск согласованных скидок | Сравнение жалоб клиентов и перевыставленных счетов |
| 3 | Уменьшить время контроля для руководителя | Снижение времени руководителя на операционный контроль выставления счетов | Опрос руководителя через 1 месяц после запуска |
| 4 | Перейти с Excel на ЛК | **Доля счетов, созданных в ЛК, ≥95%** через 1 месяц после запуска | Логи системы + данные 1С |

### 1.4 Критерии успеха

Проект считается успешным, если:

1. Снижение числа жалоб менеджеров на процесс выставления счетов до минимального уровня.
2. Исключение практики личных обходов руководителем для проверки факта выставления счетов.
3. Снижение количества жалоб клиентов на задержки и ошибки в выставленных счетах.
4. Увеличение скорости выставления счёта в 2 раза по сравнению с текущим процессом.
5. Обеспечение отклика системы не более 3 секунд на любое действие пользователя.

**Факторы успеха, которые организация может контролировать:** обучение менеджеров, качество интеграции с 1С, скорость реакции на баги.  
**Факторы вне контроля:** качество интернета в офисе, состояние старого сервера.

### 1.5 Положение о концепции

Для менеджеров по продажам и их руководителей, которые сейчас тратят время на ручное выставление счетов в Excel, допускают ошибки в прайсах и скидках, а руководитель вынужден лично контролировать каждый счёт. Личный кабинет сотрудника — это веб-портал, который позволяет выставлять счета с автоматическим применением скидок (в пределах лимита сотрудника), выбирать клиента из списка (с подсветкой «давно не покупал») и получать историю действий. В отличие от текущего процесса в Excel, наш продукт снижает количество ошибок, ускоряет выставление счетов в 2 раза и даёт руководителю прозрачный контроль без лишних вопросов.

### 1.6 Бизнес-риски

| Риск | Вероятность | Влияние | Меры снижения |
|------|-------------|---------|----------------|
| Менеджеры продолжат работать в Excel | Средняя | Высокое | Обучение, контроль руководителя, удобство ЛК |
| Старый сервер + плохой интернет → тормоза >3 сек | Высокая | Критическое | Очередь запросов, кэш, компромисс по времени |
| Данных для расчёта лимита скидок нет в системе (дата приёма) | Высокая | Среднее | Временно — константа (1 год стажа) |
| Бухгалтер не захочет заходить в ЛК | Высокая | Низкое | Уже учтено: ЛК для бухгалтера не делаем, высылаем PDF |
| Интеграция со старой 1С не сработает как надо | Средняя | Высокое | Привлечение разработчиков 1С, резервный план (Excel-выгрузки) |

### 1.7 Предположения и зависимости

**Предположения :**

1. **Данные о стаже** отсутствуют в системе. В первом релизе стаж всех менеджеров = 1 год 
2. **Пароли** у пользователей отсутствуют. Временный пароль = 123, пользователь поменяет при первом входе
3. **Почта** есть не у всех. Восстановление пароля пока через звонок админу
4. **Бухгалтер** не будет заходить в ЛК. Ему менеджер носит распечатку или скидывает PDF по почте
5. **Курьер** получает отдельный экран - не полноценный ЛК
6. **Клиенты** - не в первом релизе, но данные для них готовятся 
7. **Стажёры** - временные, им можно сделать упрощённую форму без сохранения истории
8. **Руководитель** = он же администратор в первом релизе
9. **Планы продаж** для расчёта лимита скидок будут предоставлены позже, в первом релизе могут отсутствовать
10. **Приоритеты типов скидок** будут предоставлены позже

**Зависимости :**

1. **1С** - интеграция обязательна для обмена данными о счетах, остатках, клиентах
2. **Почтовый сервер** - для отправки PDF клиентам
3. **Excel** - для загрузки прайсов (интегратор)
4. **Кадровые данные** (дата приёма) - должны быть внесены в систему после запуска, иначе лимиты скидок останутся некорректными
5. **Руководитель / Админ** - выделение времени на заведение пользователей и настройку

**Последствия нарушения зависимостей:**  
Если 1С не будет интегрирована должным образом, счета не будут синхронизироваться, и менеджеры вернутся к Excel. Если не внести реальные даты приёма - лимиты скидок будут несправедливыми, новички получат слишком высокие скидки, опытные — слишком низкие.

## 2. Рамки и ограничения проекта

### 2.1 Основные функции (первый релиз)

| ID | Функция | Краткое описание |
|----|---------|------------------|
| F1 | **Вход и безопасность** | Вход по логину/паролю, запоминание сессии, блокировка при попытке взлома (без капчи), смена пароля |
| F2 | **Дашборд** | Остатки по часто продаваемым товарам (система сама определяет «частые», если не поймёт — показывает все) |
| F3 | **Формирование счёта (PDF)** | Выбор клиента из списка (или добавление нового вручную), подсветка красным «давно не покупал», формирование PDF |
| F4 | **Скидки** | 3 типа скидок (приоритеты уточняются), применение в пределах лимита менеджера (лимит = f(стаж, план) — пока стаж = 1 год константа) |
| F5 | **Просмотр документов** | Свои счета и акты |
| F6 | **История действий** | Менеджер видит историю за 3 дня, руководитель — за месяц |
| F7 | **Экспорт в Excel** | Автоматическая выгрузка всех таблиц, которые видит менеджер, раз в день на почту (время выбирает менеджер или руководитель) |
| F8 | **Сохранение настроек** | Кнопка «сохранить настройки» (что показывать на главной) |
| F9 | **Мобильная версия** | Через браузер на телефоне (без отдельного приложения) |
| F10 | **Управление пользователями** | Только админ заводит учётные записи (нет самостоятельной регистрации) |
| F11 | **Интеграция с 1С** | Обмен данными (направления уточняются) |
| F12 | **Уведомления (по умолчанию)** | Все напоминания включены (просроченные счета, низкие остатки, день рождения клиента) — настройка позже |

### 2.2 Объем первоначально запланированной версии (Выпуск 1)

- **Только внутренние пользователи** (менеджер, стажёр, руководитель, директор (просмотр), администратор, интегратор). Клиенты — **НЕ в первом релизе**
- **Роли:** как указано выше. Для супервайзера — права как у руководителя, но без утверждения скидок
- **Функции из п. 2.1** — все перечисленные, кроме тех, что явно отложены (см. п. 2.3)
- **Интеграция:** с 1С (старой, возможно обновление), с Excel (загрузка прайсов), с почтовым сервером
- **Производительность:** максимум 3 секунды на любое действие (компромисс из-за старого сервера и плохого интернета)

### 2.3 Объем последующих версий (Выпуск 2 и далее)

| Функция | Выпуск 2 | Выпуск 3 |
|---------|----------|----------|
| **Доступ для клиентов** | Планируется (следующая очередь) | Полноценный доступ |
| **Чат внутри ЛК** (со счётом) | Можно попозже | — |
| **Настройка уведомлений** (менеджер сам выбирает, о чём напоминать) | Да | — |
| **Календарь встреч** | Как у конкурентов | — |
| **Интеграция с телефонией** | Хотелось бы | — |
| **Полноценный ЛК для курьера** | — | Позже |
| **Приложения для iOS/Android** | — | Не заявлено, но возможно |

### 2.4 Ограничения и исключения. Out of Scope для первого релиза
Клиенты не имеют доступа. Функциональность для клиентов перенесена на следующий релиз
Бухгалтер не получает ЛК. Бухгалтер работает с отчётами на бумаге или PDF по почте
Курьер не получает полноценный ЛК. Курьеру предоставляется отдельный упрощённый экран (не личный кабинет)
Нет авторизации через соцсети / Госуслуги. Только вход по логину и паролю
Нет отдельной регистрации. Учётные записи создаёт только администратор
Нет восстановления пароля через SMS. Восстановление только через звонок администратору (из-за отсутствия бюджета на SMS)
Нет капчи при входе. Капча не используется
Нет лишних подтверждений. Нет всплывающих сообщений для подтверждения операций
Нет показа чужих данных менеджерам. Менеджер видит только свои счета и документы

## 3. Бизнес-контекст

### 3.1 Профили заинтересованных лиц

| Заинтересованное лицо | Основная ценность | Отношение | Основные интересы | Ограничения |
|-----------------------|-------------------|-----------|-------------------|-------------|
| **Менеджер по продажам** | Удобное выставление счетов, контроль скидок в рамках лимита, напоминания | Основной пользователь, заинтересован в скорости и простоте | Не забывать выставлять счета, не ошибаться в прайсах, не терять клиентов | Интернет в офисе не очень, сервер старый |
| **Стажёр** | Возможность выставлять счета (но с ограничением скидки ≤5%) | Временный пользователь, нужна упрощённая форма | Не превысить лимит скидки, не допустить ошибок | Временный статус, может не быть полноценного ЛК |
| **Руководитель отдела продаж** | Автоматизация контроля выставления счетов, утверждение скидок выше порога | Сильная поддержка | Видеть счета всех менеджеров, утверждать скидки, не тратить лишнее время | Должен быть доступ ко всем ЛК менеджеров |
| **Директор** | Просмотр всего (без права изменений) | Нейтральное (ЛК не особо нужен, но если захочет доступ должен быть) | Наблюдение, отчёты | Только просмотр, никаких изменений |
| **Администратор** | Заведение пользователей, настройка, просмотр логов | Ключевая роль для запуска | Завести ЛК, выдать пароли, посмотреть логи | Нет дополнительных ресурсов |
| **Бухгалтер** | Не нужен ЛК, получает PDF на почту | Скептическое | Получать оплаченные счета для пометки | ЛК не делать, только PDF |
| **Интегратор** | Загрузка прайсов (Excel) | Техническая роль | Загрузить прайсы, даже если нет API | Работает с Excel |
| **Клиент** (будущий релиз) | Самостоятельный просмотр счетов и актов | Целевая аудитория следующей очереди | Снижение количества отвлечений менеджера на запросы клиента | В первом релизе без доступа |

### 3.2 Приоритеты проекта

По пяти измерениям:

| Измерение | Категория | Комментарий |
|-----------|-----------|--------------|
| **Функции (объём)** | Степень свободы | Часть функций может быть перенесена на последующие версии (например, чат, календарь встреч) |
| **Качество** | Ведущий фактор | Максимальное время отклика 3 секунды; исключён просмотр чужих данных пользователями с одинаковой ролью |
| **График** | Ограничение | Демонстрация работающего прототипа через 2 недели |
| **Затраты** | Ограничение | Бюджет не предусматривает дополнительных расходов (например, на SMS-уведомления или дорогостоящую оптимизацию производительности) |
| **Кадры** | Степень свободы | Привлечение дополнительных заинтересованных лиц для интервью не предусмотрено |

### 3.3 Особенности развертывания

**Доступ к системе:**
- Пользователи находятся в одном офисе, но ограничения к интернету
- Доступ через браузер с рабочего компьютера (при нестабильном интернете) и через мобильную версию в командировках.

**Изменения инфраструктуры:**
- Возможно обновление 1С (или не обновление — не определено)
- Нужна очередь запросов или кэш, чтобы тяжёлые отчёты руководителя не тормозили работу менеджеров
- Нужна интеграция с почтовым сервером для отправки PDF

**Обучение и модификация процессов:**
- Менеджеры должны быть обучены работе в ЛК, иначе останутся в Excel
- Руководитель должен получить доступ к ЛК всех менеджеров и научиться утверждать скидки
- Админ должен завести всех пользователей, так как самостоятельной регистрации нет
- Временный пароль = 123, пользователь меняет при первом входе

**Миграция данных:**
- Данные о пользователях (логин, имя) — частично есть
- Дата приёма — отсутствует → константа 1 год (потом внесут)
- Пароли — отсутствуют → временный 123

**Дополнительно:**
Учётные записи создаются для всех категорий сотрудников, включая тех, кому полноценный личный кабинет не требуется (например, бухгалтер). Для таких пользователей доступ предоставляется в минимальном объёме или заблокирован, чтобы избежать социального неравенства среди сотрудников.
